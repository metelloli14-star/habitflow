# Привычка — в ритме жизни

Сайт и приложение-трекер привычек, воды и целей в одном проекте: Next.js 15 (App Router) + TypeScript + SWR.
База данных — **PostgreSQL через Prisma** (`prisma/schema.prisma`).

## Запуск

Нужен PostgreSQL. Проще всего для разработки — `npx prisma dev` в отдельном терминале: он запускает локальный
Postgres без установки и печатает адрес вида `postgres://postgres:postgres@localhost:51214/template1?sslmode=disable`.
Подойдёт и свой Postgres (или Docker).

```bash
npm install                     # заодно генерирует клиент Prisma в db/generated
cp .env.example .env.local      # впишите DATABASE_URL
npm run db:migrate              # создать таблицы
npm run db:seed                 # демо-данные (по желанию)
npm run dev
```

Откройте http://localhost:3000 — это лендинг. Приложение открывается кнопкой «Приложение →» (адрес `/app`).

**Демо-аккаунт** (создаётся командой `npm run db:seed`): `demo@habitflow.ru` / `demo12345` —
в нём уже есть привычки, цели, история воды и статистика за 2 недели. На продакшене сид не запускается.

При регистрации нового аккаунта письмо не отправляется: код подтверждения выводится в консоль сервера
и показывается прямо на экране подтверждения (только в режиме разработки).

`npm run db:reset` — пересоздать локальную базу (все данные удаляются), после него — `npm run db:seed`.

    page.tsx         лендинг  →  /

  (mobile)/        ПРИЛОЖЕНИЕ — экраны в «рамке телефона», стили styles/app.css
    app/             /app — вход из кнопок сайта: в приложение или на экран приветствия
    (auth)/          /welcome, /login, /register, /confirm, /start, /forgot, /reset
    (app)/           /home, /water, /habits, /habits/new, /habits/[id], /goals, /stats, /profile, /menu
    documents/[slug] те же документы внутри приложения
  api/             REST API (см. ниже)
components/        UI приложения; components/site — шапка, футер и логотип сайта
lib/

  server/          сессии, валидация, бизнес-логика (services/*) — только сервер
  client/          fetch-обёртка, обработка фото
  hooks/           ХУКИ ДАННЫХ — единственный способ, которым экраны получают и меняют данные

                   db/generated — сгенерированный клиент Prisma (не хранится в git)

                   import-from-json.sql — перенос данных из старой файловой базы db/data.json

Сайт и приложение используют разные глобальные стили. Поэтому ссылки между ними — обычные `<a href>`
(полная загрузка страницы), а не `<Link>`: так стили одной части никогда не попадают в другую.

**Документы.** Тексты и реквизиты (ФИО, ИНН, email, адрес сайта https://poleznyeprivychki.ru) лежат в `lib/shared/legal/`.
Изменения автоматически появляются и на сайте, и в приложении.

| Хук / объект | Что даёт |
|---|---|

| `authApi` | `register`, `verify`, `resend`, `login`, `logout` |
| `useHabits()` | список привычек со статусом на сегодня; `createHabit`, `toggleHabit` (мгновенный отклик) |
| `useHabit(id)` | одна привычка; `updateHabit`, `deleteHabit` |
| `useWater()` | вода за сегодня; `addWater`, `removeEntry`, `setGoal` |
| `useStats()` | статистика: серии, среднее за месяц, графики недели |
| `profileApi` | `update` (имя, email, пол, фото), `deleteAccount` |
| `useReminders(habits)` | напоминания по времени привычки |

## API

Все даты — локальный день пользователя: клиент передаёт `?date=YYYY-MM-DD`.
Ошибки приходят как `{ "error": "текст для пользователя", "code": "machine_code" }`.

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/auth/register` | `{ name, email, password }` → код на почту (действует 15 мин, 5 попыток, повторно — раз в минуту) |
| POST | `/api/auth/verify` | `{ email, code }` → вход (httpOnly-cookie сессии) |
| POST | `/api/auth/resend` | повторно отправить код |
| POST | `/api/auth/login` | `{ email, password }`; после 5 неверных паролей вход блокируется на 15 мин |
| POST | `/api/auth/password/forgot` | `{ email }` → код для сброса (ответ одинаковый, есть аккаунт или нет) |
| POST | `/api/auth/password/reset` | `{ email, code, password }` → новый пароль, вход; остальные устройства разлогиниваются |
| POST | `/api/auth/logout` | выход |
| GET | `/api/auth/me` | текущий пользователь или 401 |
| GET | `/api/auth/providers` | `{ vk: 'live' \| 'mock' \| 'off' }` — показывать ли кнопку VK ID |
| GET | `/api/auth/vk/start?mode=login\|link` | переход на VK ID (PKCE) |
| GET | `/api/auth/vk/callback` | возврат с VK ID: вход, регистрация или привязка |
| DELETE | `/api/profile/vk` | отвязать VK ID |
| GET, PATCH | `/api/profile` | профиль; `{ name?, email?, gender?, avatar? }`. Новый email не применяется сразу: на него уходит код, до подтверждения работает старый |
| POST | `/api/profile/email` | `{ code }` — подтвердить новый email (после `PATCH /api/profile` с новым email) |
| DELETE | `/api/profile/email` | отменить смену email |
| POST | `/api/profile/email/resend` | отправить код на новый email ещё раз |
| DELETE | `/api/account` | удалить аккаунт и все данные |
| GET, POST | `/api/habits` | список / создать привычку |
| GET, PATCH, DELETE | `/api/habits/:id` | одна привычка |
| POST | `/api/habits/:id/toggle` | отметить / снять отметку за день |
| GET, POST | `/api/water` | вода за день / добавить `{ amount, time }` |
| DELETE | `/api/water/:entryId` | удалить ошибочную запись |
| PATCH | `/api/water/goal` | `{ goal: 1500 \| 2000 \| 2500 \| 3000 }` |
| GET | `/api/stats` | статистика |

Типы запросов и ответов — в `lib/shared/types.ts`.

## Одноразовые коды

Подтверждение регистрации, восстановление пароля и смена email используют один механизм (`lib/server/services/codes.ts`):
код из 4 цифр действует 15 минут, даётся 5 попыток, повторная отправка — не чаще раза в минуту.
В режиме разработки код выводится в консоль сервера и показывается на экране.

## Настройки (.env.local)

Скопируйте `.env.example` в `.env.local` и заполните. `DATABASE_URL` обязателен. Без настроек SMTP и VK ID в режиме разработки работают имитации:
письма печатаются в консоль сервера (а код показывается на экране), VK ID создаёт тестовый аккаунт.

### Письма с кодами
Регистрация, «Забыли пароль?» и смена email отправляют письмо с кодом через SMTP. Используйте российский
почтовый сервис — так адреса пользователей не передаются за рубеж (это обещано в политике конфиденциальности):
- **Яндекс 360** для домена poleznyeprivychki.ru: `smtp.yandex.ru`, порт 465, ящик вида `no-reply@poleznyeprivychki.ru`,
  пароль приложения (id.yandex.ru → Безопасность → Пароли приложений);
- или **Mail.ru**: `smtp.mail.ru`, порт 465.

Добавьте в DNS домена записи SPF и DKIM, которые выдаст почтовый сервис, иначе письма будут попадать в спам.
В продакшене без SMTP регистрация честно отвечает «Отправка писем временно недоступна» вместо того, чтобы потерять письмо.

### Защита от перебора и спама
- код из письма: 15 минут, 5 попыток, повторная отправка — раз в минуту;
- пароль: после 5 ошибок вход блокируется на 15 минут (сбросить — через «Забыли пароль?»);
- с одного IP: не больше 10 писем в час и 30 проверок пароля/кода за 15 минут.

Счётчики хранятся в памяти одного процесса. Если сервер стоит за nginx, он должен сам выставлять IP клиента,
иначе его можно подделать:
```nginx
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $remote_addr;
```

## Вход через VK ID

Без настроек в режиме разработки работает **имитация VK ID**: кнопка «Войти с VK ID» создаёт тестовый аккаунт
«Тестовый Пользователь VK» (на кнопке пометка «тест»). В продакшене без настроек кнопка скрыта.

Как подключить настоящий VK ID:
1. Войдите в кабинет VK ID (id.vk.ru) через VK Бизнес ID и создайте веб-приложение.
2. В настройках приложения укажите доверенный Redirect URL: `https://poleznyeprivychki.ru/api/auth/vk/callback`
   и базовый домен сайта. Включите доступ к email.
3. Создайте файл `.env.local`:
   ```
   VK_ID_CLIENT_ID=<ID приложения>
   VK_ID_REDIRECT_URI=https://poleznyeprivychki.ru/api/auth/vk/callback
   ```
4. Замените текстовый знак «VK» в кнопке (`components/auth/VkIdButton.tsx`, класс `.vkid-mark`) на официальный логотип VK ID.
   У VK есть требования к дизайну кнопки: логотип и варианты оформления берите в кабинете приложения VK ID.

Правила: аккаунт с тем же email не склеивается с VK ID автоматически — войдите по паролю и нажмите «Привязать» в личном кабинете.
Отвязать VK ID можно, только если у аккаунта есть email и пароль (пароль задаётся через «Забыли пароль?»).

## Модель данных

Выполнение привычки хранится как **журнал по датам** (`completions`: одна запись = привычка выполнена в этот день).
Отметка «сделано сегодня», серии, прогресс целей и статистика вычисляются из журнала, поэтому
не нужны ночные сбросы по таймеру: ничего не ломается, если приложение не открывали несколько дней.

## База данных (Prisma)

5 таблиц: `users`, `sessions`, `habits`, `completions`, `water_entries` — описаны в `prisma/schema.prisma`
(в коде поля в camelCase, в базе — snake_case). Сервисы (`lib/server/services/*`) работают с типами из `db/schema.ts`,
даты в них — строки `YYYY-MM-DD`; перевод строк базы в эти типы — в `db/index.ts`.

| Команда | Что делает |
|---|---|
| `npm run db:migrate -- --name <имя>` | разработка: создать миграцию из изменений `schema.prisma` и применить её |
| `npm run db:deploy` | сервер: применить новые миграции (ничего не создаёт и не удаляет данные) |
| `npm run db:seed` | демо-аккаунт (только для разработки) |
| `npm run db:reset` | разработка: пересоздать базу, **все данные удаляются** |
| `npm run db:studio` | просмотр и правка данных в браузере |

Как менять схему: правите `prisma/schema.prisma` → `npm run db:migrate -- --name add_something` → коммитите
папку `prisma/migrations/` вместе с кодом → на сервере `npm run db:deploy` (см. [docs/DEPLOY.md](docs/DEPLOY.md)).
Prisma CLI читает `DATABASE_URL` из тех же файлов, что и Next.js (`.env.local` и др.), — см. `prisma.config.ts`.

## Развёртывание

Пошаговая инструкция для сервера с PostgreSQL, nginx и HTTPS — [docs/DEPLOY.md](docs/DEPLOY.md). Коротко:
```bash
npm install
npm run db:deploy   # миграции
npm run build
npm start           # порт 3000; перед ним nginx с HTTPS
```
Для пользователей из России данные должны храниться на серверах в России (ч. 5 ст. 18 152-ФЗ):
подойдут VPS или облако в российском дата-центре (Yandex Cloud, Selectel, VK Cloud и др.).
Адрес дата-центра понадобится для уведомления в Роскомнадзор.
